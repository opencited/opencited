# OpenCited — Context

## Glossary

| Term | Definition |
|------|------------|
| **domainProject** | The canonical brand entity for a workspace. 1:1:1 mapping of organization → domainProject → brand. Contains `domain` (primary URL), `name` (display name), `aliases` (for mention detection), `logoUrl`, `active`. All feature tables reference `domainProjectId`. |
| **proxyConfig** | Per-domainProject proxy settings. Controls whether crawls use custom proxies instead of environment defaults. Has `enabled`, `sourceType` (`batch` or `api`), `sourceValue`, and `stickyProxyEnabled`. |
| **sticky proxy** | A Redis-cached "last known good" proxy, scoped per domainProject, with a 30-minute TTL. Reused on subsequent crawls for speed; cleared on failure and falls back to the full proxy list. |
| **crawl** | A single browser automation run against an AI answer engine (e.g., Perplexity) to check how a query is answered. Produces content, structured data, and brand intelligence. |
| **crawlerProvider** | A strategy adapter that knows how to drive one specific AI answer engine (Perplexity, ChatGPT, future Claude/Gemini/AI Overviews). Implements the `CrawlerProvider` interface from `@opencited/browser-crawler`. Selected at crawl time by name; instantiated by the provider factory in `packages/browser-crawler/src/providers/factory.ts`. Each provider encapsulates its own URL, DOM selectors, input mechanism, and extraction logic. The `Crawler` orchestrator is provider-agnostic. |
| **inlineLink** | A URL that an AI answer engine embeds in its response prose or displays in a dedicated sources panel. Both Perplexity and ChatGPT produce inline links — the former from `<a>` elements in the answer text, the latter from `<a class="decorated-link">` anchors or the side-panel "Sources" UI. Has `domain`, `url`, `title` (link text), `position`. Stored in `crawl_reference` with `kind = 'inline-link'` (prose links) or `kind = 'source-panel'` (panel links). The `citationScore` sub-score reads both kinds and asks the same question: "is the brand's own domain in the reference list?" — treating each domain as binary (cited or not) regardless of how many reference rows exist for it. _Avoid_: citation, citationSource (deprecated — these were inline links all along). |
| **providerFactory** | The registry in `packages/browser-crawler/src/providers/factory.ts` that maps a provider name string to a constructor. The worker calls `createProvider(name, logger)` and gets back a configured `CrawlerProvider` instance. Adding a new provider means adding one entry to the factory map. Replaces the prior hardcoded `new PerplexityProvider()` call sites in the worker and tRPC router. |
| **crawlReference** | The polymorphic DB table that stores all reference links from AI answer engines in one place. Columns: `crawlId`, `kind` (`'inline-link' \| 'source-panel'`), `position`, `url`, `domain`, `title`, plus optional fields. Both Perplexity and ChatGPT produce `inline-link` rows (from prose anchors); ChatGPT also produces `source-panel` rows (from the side-panel "Sources" UI). The `citationScore` action reads from this one table, deduplicates by domain (binary per domain), and asks "is the brand's own domain in the reference list?" — engine-agnostic. ADR: `docs/adr/0003-multi-provider-architecture.md`. |
| **providerRateLimit** | A per-provider request rate cap, configured via the `CRAWL_RATE_LIMITS` env var as a JSON map (e.g. `{"perplexity": {"rps": 0.5}, "chatgpt": {"rps": 0.2}}`). Enforced in the worker's job handler before dispatch. Protects providers that have stricter anti-bot thresholds (ChatGPT shows a Google sign-in popup to detected automation) from being burned through too fast. Proxies handle IP-level rotation; the rate limit handles request-level throttling. |
| **promptQuery** | A saved search query associated with a domainProject. Can have multiple crawls over time. |
| **sitemap** | A registered sitemap URL for a domainProject, used to discover pages to analyze. |
| **competitor** | A competing brand/domain tracked within a domainProject for mention comparison. |
| **brandMention** | A detected mention of the target brand or its aliases in AI-generated content. |
| **mentionPosition** | 1-indexed ordinal rank of a brand mention among all brand mentions detected in a single AI answer, in order of first appearance. Captured on `crawl_brand_mention.position` (integer, nullable for legacy rows). Used by the position sub-score of the AI Visibility Score. |
| **visibilityScore** | A composite 0–100 number expressing how visible a brand is in AI-generated answers. Computed at three layers: per-crawl (raw formula output, stored on `crawl_visibility_score`), per-prompt (mean of per-crawl scores for that prompt), and per-brand-per-engine (min-max normalised against the tracked competitor set). Formula: `0.35 × mentionScore + 0.25 × positionScore + 0.20 × citationScore + 0.10 × sentimentScore + 0.10 × coMentionScore`. Authoritative spec: `docs/agents/visibility-score.md`. ADR: `docs/adr/0002-visibility-score.md`. |
| **sub-score** | One of the five components of the `visibilityScore`: `mentionScore` (binary presence), `positionScore` (`100 / log2(1 + rank)` decay), `citationScore` (own-domain cited as source), `sentimentScore` (LLM-as-judge mapped from positive/neutral/negative to 100/50/0), `coMentionScore` (target's share of brand mentions in the answer). |
| **peer set** | The set of brands used as the normalisation baseline for a domainProject's `visibilityScore` at the per-brand-per-engine layer. Consists of the target brand plus its tracked `competitor` rows. Empty peer set (no competitors tracked) is an explicit cold-start state — the score is `null`, not zero. |
| **formulaVersion** | A version string (e.g. `v1.0.0`) stored on every `crawl_visibility_score` row. Bumped on every change to the score formula or weights. A one-off migration can re-score all historical crawls with a new version while preserving the old. |
| **sentimentFallback** | A boolean (`sentimentIsFallback` on `crawl_visibility_score`) indicating the sentiment sub-score defaulted to neutral (50) because the LLM call timed out or returned a parse error. Triggers a background retry (1 max) and a user-facing "Retry sentiment analysis" affordance in the crawl detail sheet. |
| **promptTemplate** | A system-curated, pre-built prompt available in the prompt library (Library tab within `/app/prompts`). Independent of any domainProject. Has a human-readable slug `id` (e.g. `competitor-price-comparison`). Contains `text` (the query, may include `{brandName}` placeholder), `title`, `description`, `industry` (enum: SaaS, E-commerce, Healthcare, Finance, Media & Publishing, Education, Travel & Hospitality, Real Estate, Legal Services, Marketing & Advertising), `category` (enum: competitor-analysis, brand-monitoring, visibility, content-optimization, pricing-intelligence, feature-comparison), and `tags` (predefined array). Seeded from a hardcoded TS file (`packages/db/src/prompt-templates.ts`) via `bun run sync:templates`. When a user adds a template, `{brandName}` is auto-resolved from `domainProject.name` (falling back to `domainProject.domain`), then presented in a dedicated `AddTemplateDialog` (showing metadata + editable text) before saving as a `promptQuery`. Once copied, the prompt is fully owned by the user — template updates do not propagate back. |

## Proxy Resolution Order

When a crawl job runs, proxies are resolved in this order:

1. **Custom proxyConfig** (if enabled for the domainProject) — either a batch list or an API URL
2. **`THORDATA_PROXY_API_URL`** env var — platform-wide proxy API
3. **`PROXY_SERVER`** env var — single proxy fallback
